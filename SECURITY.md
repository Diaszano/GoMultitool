# Security policy

Report suspected vulnerabilities privately to the repository maintainer through GitHub's private vulnerability reporting feature when it is available. If private reporting is unavailable, contact `@Diaszano` directly through GitHub. Do not post credentials, exploit details, private keys, or an unpatched vulnerability in a public issue.

Include the affected commit or release, impact, and steps to reproduce. The maintainer will acknowledge reports and coordinate a fix and disclosure timeline. Do not test recovery or boot vulnerabilities on devices or storage you do not own or have permission to test.

The default branch is the supported software line. Recovery images remain experimental until hardware compatibility has been validated and approved; see [the release policy](docs/releases/release-policy.md).
